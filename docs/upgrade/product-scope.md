# 产品范围

## 产品定位

Resource Timeline 是一个长期驻留、低干扰、以时间线回溯为核心的 Windows 本地工具。它不是硬件超频面板，也不追求展示每个传感器；它回答三类问题：

- 某个时间点，CPU、GPU、内存、磁盘以及主要进程发生了什么？
- 一天中电脑和各应用实际使用了多久？
- 蓝屏、异常掉电或重启前后，资源与进程数据发生了哪些变化？

## 计划支持的常用指标

| 类别 | 默认候选指标 | 说明 |
| --- | --- | --- |
| CPU | 使用率、温度、封装功耗、有效/平均频率 | 不默认采集逐核心电压等高维传感器 |
| GPU | 使用率、温度、板卡功耗、核心频率、显存占用 | 多 GPU 独立设备记录 |
| 内存 | 已用量、使用率、可用量 | 总容量属于设备/会话元数据 |
| 磁盘 | 读写速率、温度 | 容量和型号属于设备元数据 |
| 网络 | 上传/下载速率、链路与 Wi-Fi 状态 | 按物理接口保存，默认汇总排除回环和重复虚拟流量 |
| 电池 | 电量、充放电功率、AC/充电状态、健康度 | 只在探测到电池时启动 Battery Provider |
| 进程 | CPU、工作集/私有内存、GPU、磁盘/网络 I/O、选择原因 | 详细样本只保存诊断价值高的集合，长期另存聚合 |

指标是否可用由硬件、驱动、权限和 Provider 决定。UI 必须区分“用户关闭”“设备不支持”“暂时读取失败”，不能都显示为 0。

## 用户控制

设置分为两级：

1. 类别开关，例如关闭 GPU 采集。关闭后停止 GPU Provider 的轮询与写入。
2. 指标开关，例如保留 GPU 使用率但关闭温度。CollectionPlan 不再请求该指标，存储层不写伪造值。

默认配置应覆盖常用指标，但只启用通过快速能力探测确认可用且成本可接受的项。设置变化即时生成新计划，不要求重启应用。普通用户选择轻量、均衡或详细预设；高级设置再按类别/指标调整。Windows 节能模式下默认自动切换轻量采集，用户可以关闭该行为。

## 条件指标与首版排除

以下指标只在来源可靠、额外开销可接受时提供：CPU 热节流、GPU Hotspot、GPU 热限制、内存频率/温度、风扇/水泵、屏幕亮度和真实整机功耗。内存频率只在启动或设备变化时读取；屏幕亮度只使用变化事件和低频兜底。

刷新率和 HDR 状态不进入首版采集范围。不会为了让“部件功耗合计”更完整而新增意义有限或代价较高的传感器。

## 三个相互关联的产品视图

### 资源时间线

展示系统指标曲线和同一时刻的高资源进程，用于日常回溯和异常定位。

### 使用统计

展示电脑 Active/Idle/Locked/Sleep 状态、应用前台时长和分类分布。默认不记录窗口标题；用户明确开启后才记录经隐私规则处理的上下文。

### 崩溃回溯

应用启动时检查上次检查点之后是否出现 BSOD、意外关机或异常重启。没有证据则不打扰用户；有证据则建立 crash case，保护证据时间窗并展示关键节点前后的原始曲线、系统事件和客观统计摘要。

## 非目标

- 不取代 HWiNFO、MSI Afterburner 等专业传感器/超频工具。
- 不保证覆盖所有主板 EC、VRM、电压、风扇和逐核心传感器。
- 不根据资源曲线输出崩溃原因、诊断结论、可能性排行、严重度或处理建议；原因排查由用户完成。
- 不默认采集窗口标题、键盘输入、屏幕内容、文件内容或网络内容。
- 不在本阶段引入云端同步、账号体系或遥测上传。

## 隐私与本地优先

所有数据默认只存储在本机。窗口上下文为显式 opt-in，支持排除应用、标题脱敏和单独清除。设置页应显示数据库总占用（主库、WAL、SHM）、各类数据的估算占用和保留时长。
